🔹 Spark / PySpark
1️⃣ What is a Spark Cluster?
A Spark cluster is a distributed computing environment where multiple machines process data in parallel. It consists of a Driver node that coordinates execution and multiple Executors running on worker nodes that process data partitions.

2️⃣ Driver vs Executor?
Driver: Creates Spark session, builds execution plan (DAG), coordinates tasks.


Executor: Executes tasks, processes partitions, stores data in memory.


Driver = coordinator. Executors = workers.

3️⃣ Driver OOM vs Executor OOM?
Driver OOM: Seen in driver logs. Usually caused by collect() or large broadcast.


Executor OOM: Multiple task failures, executor lost errors. Caused by skew, large partitions, heavy joins.


Check CloudWatch logs / Spark UI to confirm.

4️⃣ What is Checkpointing?
Checkpointing is basically saving the intermediate result of a Spark job to a safe location like S3.
In Spark, when we apply many transformations, Spark keeps track of all steps in something called lineage. If the job fails, Spark recomputes everything from the beginning.
So by using checkpointing, we save the data at a certain point.
 If something fails later, Spark does not need to recompute from the very start — it resumes from the checkpoint.
It improves:
Fault tolerance


Stability of long-running jobs


Performance in complex pipelines




5️⃣ How did you implement checkpointing?
In our project, we used checkpointing in long transformation pipelines where multiple joins and aggregations were involved.
We stored checkpoint data in S3 to ensure durability.
This helped us avoid recomputation and improved reliability of monthly batch jobs.

7️⃣ What is Sort Merge Join?
Used when both datasets are large. Spark shuffles and sorts both datasets on join key and then merges them efficiently.

8️⃣ Broadcast vs Sort Merge Join?
Broadcast Join → One table small, no shuffle on big table.


Sort Merge Join → Both tables large, requires shuffle.



9️⃣ If both datasets are very large?
Use Sort Merge Join.
 Repartition on join key and handle skew if required.

🔟 DataFrame vs DynamicFrame?
DataFrame → Strict schema, better performance.


DynamicFrame → Flexible schema, handles semi-structured data and schema evolution.

13.1What is Data Skew? (Simple Human Explanation)
Data skew happens when:
👉 Some partitions have much more data than others.
In distributed processing (like Spark), data is divided into partitions and processed in parallel.
If one partition has 10x more data than others:
That executor will take much longer


Other executors will sit idle


Job becomes slow


Sometimes causes OOM


That is called data skew.

4️⃣3️⃣What are Wide and Narrow Transformations?
This is a very common Spark question.

✅ Narrow Transformation
A narrow transformation is when:
Each output partition depends on only one input partition.


No shuffle required.


Examples:
map()


filter()


select()


withColumn()


It is fast because there is no data movement across nodes.

✅ Wide Transformation
A wide transformation is when:
Output partition depends on multiple input partitions.


Requires shuffle.


Data moves across executors.


Examples:
groupBy()


join()


distinct()


repartition()


It is expensive because it involves network shuffle.
